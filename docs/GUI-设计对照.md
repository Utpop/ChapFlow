## 1.1 阅读器：内置还是外置（调研结论）

| 方案 | 依赖/体积 | 渲染能力 | 数据与图片 | 结论 |
|---|---|---|---|---|
| **QTextBrowser**（内置） | 随 QtWidgets，**0 新增** | HTML4 + CSS2 子集：段落/标题/列表/表格/图片/字号够用；无 JS、无 flex/grid | 图片直接从 EPUB 内存读取，不落盘 | ✅ 采用 |
| QtWebEngine（内置 Chromium） | 需 `PySide6-Addons`，约 **+150 MB** | 接近浏览器 | 本地渲染 | ❌ 体积代价过大，本机未装 |
| 外置阅读器 / 浏览器 | 需导出临时文件 | 取决于外部程序 | 临时文件落盘、相对路径易断图、丢失当前书上下文 | ❌ |

实现要点：`EpubView.loadResource` 用 `epub:/<包内路径>` 自定义 URL 直接返回图片字节；
书内 `<link rel=stylesheet>` 的内容内联进文档（去掉 `@font-face`/`@import`），`<script>` 全部剥离；
`text-indent` 在 QTextBrowser 上不稳定，改用 `QTextBlockFormat.setTextIndent` 兜底，居中标题与 heading 跳过。

## 2. 规范与视觉稿的不一致，及处理方式

**A. 工具栏“TXT 导入” vs 实际支持 DOCX**

视觉稿只写 TXT。项目已有 DOCX 导入（规范要求“呈现已存在功能”）。
处理：按钮文案改中性词 **「导入」**，tooltip 注明“TXT / DOCX”，对话框按扩展名切换选项（DOCX 隐藏编码/段落选项，改为“按几级标题切章”）。
不采用“TXT 导入”+ 偷偷支持 docx 的做法，避免文案与行为不符。

**B. 视觉稿出现“番外（空组）”，但引擎导出会丢弃空大标题**

这是真实的规范冲突，不是实现缺陷：EPUB3 nav 中 `<li><span>` 必须跟**非空** `<ol>`，空分组会触发 `RSC-005: li incomplete`（已用 EPUBCheck 5.4.0 验证）。
处理：
- 树里**允许**存在空大标题（视觉稿也这么画），并在删除/导出时如实处理；
- 导出时丢弃，并在自检报告 `warnings` 与操作日志中提示“有 N 个空大标题未写入目录”；
- 未伪造占位子项来“凑”一个合法空组。

**C. 状态栏“UTF-8”**

EPUB 内容文档按规范必须是 UTF-8，状态栏写 UTF-8 对**当前书**恒成立；而导入 TXT 的编码因文件而异。
处理：状态栏固定 `UTF-8` 并加 tooltip 说明；**TXT/DOCX 导入的实际编码显示在导入对话框与操作日志**，不在状态栏混用两个概念。

**D. 视觉稿“ISBN 978-7-5366-9293-0”**

`dc:identifier` 可能不是 ISBN。处理：仅当标识符符合 ISBN-10/13 形状（10/13 位数字，允许末位 X）时显示为 `ISBN …`；否则不显示该字段，绝不编造。

**E. 视觉稿“第 2 层 · 大标题下 / 撤销 · 12 步 / 128 项 / 134 通过”等示例数值**

全部改为实时计算：层级来自树深度、步数来自撤销栈、条目数来自 `count_nodes`、报告数字来自 `validate` 结果。

**F. 视觉稿合并对话框是 1→2→3 三步向导（含“上一步”）**

引擎的合并是**一次调用**完成（选书 → 选项 → 执行），拆成三步属于虚构流程。处理：保留步骤条但只点亮第 1 步「选择书籍」，选项、排序、预览同页完成，底部为「取消 / 开始合并」。若后续真要做分步向导，需要业务层支持“暂存合并计划”。

**G. 规范要求 PySide6；项目此前主打“零依赖便携”**

PySide6 是第三方依赖（约 100 MB）。处理：**引擎层保持零依赖**，GUI 作为独立入口 `src/chapflow_gui.py`；不装 PySide6 时 CLI 仍可用。打包 exe 时用 PyInstaller 一并封装（GUI 依赖随包分发，用户无需装 Python）。

**H. 实际使用反馈：菜单栏整行占高、信息密度低**

规范 §3.1 要求菜单栏，但用户要求删掉这一行。处理：`menuBar().setVisible(False)` 隐藏，
把同一批 `QAction`（导入 / 合并 / 校验 / 新增大标题 / 打包 / 删除 / 关于 / 退出）收进工具栏最右的
**「⋮」更多按钮**，快捷键（Ctrl+O/I/M/S、Alt+↑↓、Delete、F5）全部保留，功能没有丢失。

**I. 窄窗口 / 小高度下的重叠**

1080×707 时详情卡被压到 236px（内容需 268px），复选框与按钮行重叠、删除按钮逼近卡片边缘。
处理：详情卡最小高度提到 272px 并缩短按钮文案（「打包成大标题」「删除…」），按钮行内边距收紧；
书籍信息卡内容改为 `QScrollArea`，窗口变矮时滚动而不是把封面与统计行压在一起。
已在 1080×707 与 1500×980 两档实测无重叠。

**O. 新增「新建书」入口**

设计稿只画了「TXT 导入」（追加到当前书）。实际还需要“从零建一本书”，因此在工具栏「打开」之后
加了「新建书」：选 TXT/DOCX → 填书名/作者/语言 → 预览章节 → 生成并自动打开。
与「导入」的分工写在 tooltip 里：一个生成新书，一个追加到当前书。

**N. 阅读器不在设计稿内**

视觉稿没有阅读功能。按“不虚构功能”的原则，这一项是被明确要求新增的，
因此只做成**只读预览**（不改内容），入口放在双击章节与右键菜单，不占用主界面空间。

**L. 实际反馈：去掉工具栏最右的「⋮」按钮**

该按钮原本承载“菜单栏隐藏后的入口”。用户要求去掉后：导入 / 合并 / 校验 / 新建大标题 均已是工具栏按钮，
删除与上下移在右键菜单与快捷键里；「关于」改为点击标题栏的 **ChapFlow** 名字（悬停有提示）。
菜单栏仍隐藏，快捷键不受影响。

**M. 校验后修复**

自检报告底部新增「修复 N 项并重新检查」，只自动处理**能安全判断**的问题：
目录中指向缺失文件的条目、空大标题（模型层，可撤销）；
文件清单失效项、正文顺序无效引用、唯一标识错误则在导出时自动清理并计入报告。
无法判断的问题（例如文件内容缺失但仍有引用）不会被“猜着修”。

**K. “新增大标题”与“打包成大标题”合并为一个按钮**

两个动作本质都是“建分组”，只是入口不同。合并为工具栏的**「新建大标题」**（Ctrl+G）：
选中了条目 → 把选中的同层连续条目打包进新大标题；没选中（点目录空白处取消选择）→ 在末尾新建空大标题。
详情卡里的「打包成大标题」按钮随之移除，按钮行更清爽；tooltip 写明两种行为。

**J. 规范 §3.1 菜单有“新增章节”，但引擎只能新建大标题**

引擎不支持凭空创建正文页（会产出空章节，无意义）。处理：菜单与工具栏只放 **「新增大标题」**；「新增章节」不出现，避免点了才提示“暂不支持”。

## 3. 代码结构

```
src/
├── chapflow.py          引擎 + CLI（零依赖，本轮仅新增 redo / cover / 两项元数据校验）
├── txtconv.py           TXT 解析
├── docxconv.py          DOCX 解析
├── xmldom.py            轻量 XML DOM
├── chapflow_gui.py      GUI 入口
└── ui/
    ├── tokens.py        颜色 / 尺寸 / 字体令牌
    ├── theme.py         浅色 QSS（全部引用令牌）
    ├── fonts.py         字族解析与系统中文字体兜底
    ├── icons.py         线性图标（QPainter 绘制，统一 1.8px 描边）
    ├── models.py        ChapterTreeModel（QAbstractItemModel）+ 过滤代理 + 拖放
    ├── widgets.py       卡片 / 统计行 / 封面 / 日志 / 点阵背景 / 空状态 / 两个委托
    ├── dialogs.py       导入、合并、自检报告、关于
    └── main_window.py   主窗口与全部交互
```

界面只做三件事：**渲染 `Session` 状态**、**收集用户意图**、**调用引擎方法**。
没有为了视觉效果改写 EPUB 解析、目录同步、排序或导出逻辑。

## 4. 运行

```bash
# 1) 安装 GUI 依赖（仅首次，装到你要用的那个 Python）
py -3 -m pip install PySide6-Essentials

# 2) 启动
py -3 src/chapflow_gui.py                  # 空白界面
py -3 src/chapflow_gui.py book.epub        # 直接打开
```

Windows 双击项目根目录的 **`ChapFlow.bat`**：脚本会依次探测 `py -3`、`python` 与常见安装位置，
**只采用真正能 `import PySide6` 的解释器**，再用同目录的 `pythonw.exe` 无控制台启动。
探测失败时会打印安装命令并 `pause`（不再闪退）；任何启动异常都会写入 `logs/gui-error.log`
并弹出系统提示框。

> 常见坑：机器上可能同时存在多个 Python（例如 3.15 与 3.13）。`pip install` 装到 A，却用 B 启动，
> 表现就是"双击没反应"。脚本按"能否 import"选择解释器，正是为了避开这个问题。

环境要求：Python 3.10+（PySide6 6.12 要求），Windows 10/11；引擎部分仍支持 Python 3.8+。
