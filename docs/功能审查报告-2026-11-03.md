# ChapFlow 功能有效性与一致性审查

> 审查日期：2026-11-03　｜　代码版本：v1.3.0（`src/chapflow.py` `__version__`）
> 审查对象：引擎 15.8k 行（`src/`）、界面层、CLI、测试套件、`README.md` 与 `docs/功能清单.md`
> 与 `docs/代码审查报告.md` 的关系：那份报告审**代码质量与安全**，本报告审**功能是否按契约工作、彼此是否自洽**

## 二、结论摘要

主体功能有效：三处同步、卷标题页、playOrder 去重、EPUB2→3、合并资源隔离、原子写盘、mmap 打开在生产样本与 EPUBCheck 复核下均表现正确。

但存在 **2 个高severity 缺陷**（元数据局部更新丢书名、正文编辑残留旧文字）、**5 个中等缺陷**（修复误删子章、删除不清理新增文件、卷正文文件不清理、远程资源误报导致无法保存、DOCX 层级被压平）与 **5 个低severity 问题**，另有 **6 处跨模块不一致** 与 **4 处文档漂移**。

一句话概括：**"改目录"这条主干是可靠的；"改内容 / 改元数据 / 修问题"三条旁路各有会丢数据或说谎的角落。**

## 四、缺陷清单

### D1【高】局部元数据更新会清空书名；清空字段留下空元素

**位置**：`src/chapflow.py:2960-2965`（`update_metadata`）、`1281-1300`（`_set_dc`）

**现象**：

```python
s.update_metadata({"creators": ""})     # 只想清空作者
# 结果：<dc:title id="title"/>  <dc:creator id="creator"/>
```

- `title` 未做 `is not None` 保护，任何局部字典都会把书名写成空、并删掉 `file-as` 排序名。
- `_set_dc` 对空值执行 `children = []`，留下**空元素**而不是移除元素。

**EPUBCheck 5.4.0 实测**：

```
ERROR(RSC-005) dc:title:  character content ... must be a string with length at least 1
ERROR(RSC-005) dc:creator: character content ... must be a string with length at least 1
```

而内置 `validate_bytes` 对同一文件**全部 ok**——自检说通过、规范检查说错误，正好违反 README "0 error 0 warn" 的承诺。

**影响**：GUI 里把"作者"清空后保存，会写出不合规的包且自检不报警；引擎侧任何局部调用都会静默丢书名（数据丢失）。

**修复建议**：
1. `title` 改为 `if values.get("title") is not None:`，与其它字段一致；
2. `_set_dc`/creator 分支在值为空时 `detach(md, node)`（`dc:title` 至少保留一个，但必须有非空文本）；
3. `validate_bytes` 增加"空 `dc:title` / `dc:creator` / `dc:identifier`"判 error。

**可验证断言**：

```python
s.update_metadata({"creators": ""})
assert s.metadata()["title"] == "测试之书"            # 不再被清空
out = s.export(p); assert not [i for i in E.run_epubcheck(out) if i["level"] == "error"]
```

### D2【高】阅读器改正文：段数不变时旧行内文字残留

**位置**：`src/chapflow.py:2071-2075`

```python
if para != _edit_text(b):
    keep = [c for c in b.children if c.kind == "element"]
    b.children = [tx(para)] + keep        # ← 旧元素带着旧文字被追加在新文字之后
```

**实测**（原文 `<p>他<em>轻声</em>说道：“走吧。”</p>`，改为"他大声喊道：“快走！”"）：

```html
<p>他大声喊道：“快走！”<em>轻声</em></p>
```

**影响**：渲染出"他大声喊道：“快走！”轻声"——用户改过的段落出现重复残句，且随保存写回正文。这是文档承诺的"保留段内加粗、斜体与图片原位保留"的反面：格式留下了，文字却重复了。

**修复建议**：文本变化时不保留旧的文本承载元素，改为"仅当段落文本未变化才保留子元素"；或按变更做简单的行内片段对齐（保留图片 `img`、丢弃纯文本行内元素），并在 UI 提示"本章含行内格式，段内格式将重排"。

**可验证断言**：

```python
out, rep = E.apply_chapter_text(html, "他大声喊道：“快走！”\n\n第二段加粗结尾。")
assert "轻声" not in out and "说道" not in out
```

### D3【中高】修复会把"正文页缺失的卷"连同全部子章一起删除

**位置**：`src/chapflow.py:3351-3364`（`repair`）

```python
if n.file and n.file not in alive:
    removed_dead += 1
    continue          # ← 不再递归，整条（含子章）丢弃
```

**实测**：卷"第一卷 试炼"（`kind=doc`，正文页丢失）下有两章有效章节：

```
修复前: [('doc','第一卷 试炼',2), ('doc','第三章 远行',0), ('doc','第四章 归途',0)]
plan:   [('dead', '目录里有 1 个条目指向不存在的文件')]
修复后: [('doc','第三章 远行',0), ('doc','第四章 归途',0)]
```

**影响**：用户看到"1 个条目"、点一下修复，实际丢掉 2 章目录（正文文件仍在包里，但目录不可达）。`repair_plan` 的计数与真实影响严重不符，属于**点了就丢数据**。

**修复建议**：卷自身文件失效时，只清空 `n.file`（降级为纯分组）并递归子项，不要丢弃节点；`plan` 文案区分"降级 N 个卷 / 移除 M 个悬空章节"。

**可验证断言**：

```python
s.repair()
assert [n.title for n in s.toc] == ["第一卷 试炼", "第三章 远行", "第四章 归途"]
assert s.toc[0].file is None and len(s.toc[0].children) == 2
```

### D4【中】删除本次新增的章节，文件与 manifest 项残留在产物里

**位置**：`src/chapflow.py:2318-2323`（`_mark_removed` 只查 `book.manifest`）

**实测**：

```
新增 chap-001.xhtml → 删除该条目（physical=True）→ 导出
```

**影响**：产物里留下"目录看不到、spine 也没有"的孤立 XHTML 与 manifest 项（EPUBCheck 不报错，但包体与清单被污染，用户重复"加一章→删掉"会持续膨胀）。与 README "连同正文文件一并删除"、功能清单"撤销后新增文件不残留"的语义相冲突。

**修复建议**：`_mark_removed` 同时处理 `new_files` / `new_manifest` / `spine_append`：命中则直接删除对应登记（这些文件从未落盘，无需进 `removed`）。

**可验证断言**：

```python
assert all(m["path"] != path for m in s.new_manifest)
with zipfile.ZipFile(out) as z: assert not any("chap-001" in n for n in z.namelist())
```

### D5【中】可点击卷自身的正文文件永不标记删除

**位置**：`src/chapflow.py:2296-2310`（promote / cascade 两分支都跳过 `kind=="group"`）

**实测**（卷自身正文 = `ch03`，先移出引用它的条目）：

```
removed: ['OEBPS/Text/ch01.xhtml', 'OEBPS/Text/ch02.xhtml']
ch03 仍打包: True
```

**影响**：`physical=True` 只删子章、漏掉卷自己的那一页，包内留下无引用文件；与"物理删除"承诺不一致。

**修复建议**：删除前先 `if node.file: self._mark_removed(node)`（promote 分支还需确认该文件未被其它节点引用），cascade 分支把 `kind != "group"` 的判断改为"有 file 即登记"。

### D6【中】远程资源被误判为"manifest 引用缺失"，导致无法保存

**位置**：`src/chapflow.py:1839`（`missing = [... if m["path"] not in fileset]`）

`resolve_href` 对外链返回 `None`，manifest 项 `path` 落为空串，空串不在 ZIP 里 → 判 error，且报错文本是"manifest 引用缺失："（后面空白）。

**实测**：给 OPF 加一条合法远程样式表（`properties="remote-resources"`）：

```
['manifest 引用缺失：']
```

**影响**：EPUB3 允许远程资源；这类书在 GUI 里"保存到原文件"会被 `save_in_place` 的干跑校验直接拦下（"已取消，原文件未改动"），用户无法保存任何编辑。报错还无法定位（名字为空）。

**修复建议**：`resolve_href` 返回 `None` 时按外链处理（跳过存在性检查，并在报告里单列"远程资源 N 项"）；校验信息带上 `id`。

**可验证断言**：

```python
assert not [i for i in E.validate_bytes(data) if i["level"] == "error"]
```

### D7【中】"修复"补卷标题页不进撤销栈，导出也会静默改模型

**位置**：`src/chapflow.py:3268-3293`（`fix_swallowed_groups` 无 `push`）、`3390-3394`（`export` 调用它）

**实测**：

```
repair 日志: ['给 1 个大标题补了卷标题页…']    undo 深度: 0    可撤销: False
```

**影响**：
- 违反 README "修复可撤销"；
- `export()`（包括"另存为"）会改动 `self.toc` 的 `file`、追加 `new_files`/`new_manifest`/`spine_append` 并置 `dirty=True`：用户什么都没做，只是导出一次，状态就变成"未保存"，且无法撤回；
- 因 `dry_run=True` 跳过该步骤，干跑与写盘的包内容不同源（见 D10）。

**修复建议**：`fix_swallowed_groups` 内部 `push()`（或由 `repair()` 统一 push）；`export` 改为在副本上补齐（`clone_toc`），导出不改会话状态。

**可验证断言**：

```python
before = s.undo_depth; s.repair()
assert s.undo_depth == before + 1 and s.undo()
assert not s.dirty
```

### D8【中】DOCX 多级标题在追加与转书时被压平，与 TXT 不一致

**位置**：`src/chapflow.py:2718`（`append_docx` 全部 `Node("doc")`）、`4022`（`docx_to_epub` 同样）

**实测**（`sample.docx`，`split_level=2`）：

```
read_docx → [(1,'第一章 来自 Word'), (1,'第二章 表格与图片'), (2,'2.1 一个小节')]
追加后    → '第二章 表格与图片'(0 子项)、'2.1 一个小节'(0 子项)   # 2.1 与第二章同级
```

**影响**：`split_level=2` 的语义是"按 2 级标题切章并保留层级"，实际却把 2.1 提升为一级条目；而 TXT 导入会把 `第X卷` 建成分组。同一产品里"卷 → 章"的建模在 TXT 与 DOCX 两条入口不一致，`_bucketize`、编号、批量移动等依赖层级的功能随之失真。

**修复建议**：按 `Chapter.level` 维护一个层级栈（`level` 小于当前栈顶则出栈），与 `txt_to_epub` 的 `container` 逻辑统一；抽出公共 `nodes_from_chapters(chapters)` 供 `append_txt` / `append_docx` / `txt_to_epub` / `docx_to_epub` 共用。

**可验证断言**：

```python
s.append_docx("sample.docx", split_level=2)
assert s.toc[-1].children[0].title == "2.1 一个小节"
```

### D9【低】编号重排会改"单位"；分卷编号在部→卷→章 混排时按"部"计数

**位置**：`src/chapflow.py:3732-3734`（`_format_title` 用 `chosen["unit"]`）、`3781-3786`（`_bucketize`）

**实测 1**（章/节各 2 个）：

```
第三节 远行 → 第三章 远行
第四节 归途 → 第四章 归途
```

README §3.9 写的是"重排时仅替换编号部分，标题文字不作改动"——单位被替换，属**文档与实现相反**。

**实测 2**（第一部 = [第一卷[第一章 甲], 第二章 乙]，第二部 = [第一章 丙]）：

```
单元: 第一部  条目数 2 ['第一章 甲','第二章 乙']
单元: 第二部  条目数 1 ['第一章 丙']
```

卷"第一卷"的边界丢失，其章节与"部"直属章节混编成一个 1..N 序列。文档承诺"部→卷→章 按卷划分"。

**影响**：对卷/节结构的中文书，重排会改写用户不想动的单位词；独立编号在混排结构下产生错误编号。

**修复建议**：`chosen` 只决定"数字形式（中文/阿拉伯）与前缀"，单位沿用每条自身的 `info["unit"]`（无编号补号时才用默认单位）；`_bucketize` 遇到"混合层级"时递归到最深的同层大标题分桶，而非按第一个含叶子的层截断。

**可验证断言**：

```python
for c in s.renumber(): assert c["new"].endswith(c["old"].split(" ",1)[1])
assert [g["label"] for g in s.numbering_plan(per_group=True)["groups"]] == ["第一卷","第二部"]
```

### D10【低】`dry-run` 与真实导出的报告不等价

**实测**（同一本书、同一选项）：

```
dry-run: volume_pages=[{'path':'OEBPS/Text/part01.xhtml',...}]  added_files=[]
real   : volume_pages=[]                                        added_files=['OEBPS/Text/part01.xhtml']
```

同一份产物，两个字段互换来源；`save_in_place` 先 `dry_run` 再真实导出，等于对两个不同构造路径各算一遍（且第二次才发现卷页已在会话里）。CLI `--dry-run` 打印的目录树也可能与真实导出不一致（`--dry-run` 不加卷页）。

**修复建议**：把"补齐卷页 / 丢弃空组"下沉到 `export_epub` 单一入口（`Session.export` 不再预处理），`dry_run` 与写盘走完全相同的路径，仅最后 `if not dry_run: 写文件`。

**可验证断言**：

```python
d = s.export(os.devnull, dry_run=True); r = s.export(out)
assert d["volume_pages"] == r["volume_pages"] and d["added_files"] == r["added_files"]
```

### D11【低】自检不查 manifest id 重复、空 `dc:*`、XHTML 可解析性

**实测**：给 OPF 复制一条 manifest 项（同 id）→ `validate_bytes` **全部 ok**，EPUBCheck 报 3 条 RSC-005。

README §3.8 明确列出"id 是否重复"，实现中没有任何去重判断（`grep "重复"` 无相关代码）。同理，空 `dc:title`（D1 产物）与正文 XHTML 解析失败也不会被自检发现——后者恰恰是"阅读器打开空白但自检通过"的典型来源。

**修复建议**：补三条检查（id 唯一性、必需 `dc:*` 非空、spine 中每个 XHTML 能被 `parse_xml` 解析），均判 error；或在 README 中删掉未实现的承诺。

### D12【低】覆盖写盘无重试，瞬时占用会让保存失败并留下 `.tmp`

**位置**：`src/chapflow.py:3414`（`os.replace`）

首次运行 `tests/run_tests.py` 时实测一次：

```
PermissionError: [WinError 5] Access is denied: '...inplace.epub.tmp' -> '...inplace.epub'
```

复跑即通过。Windows 上杀毒/索引器/资源管理器预览对目标文件的瞬时占用会触发 `WinError 5/32`，当前实现无重试、无回退，`.tmp` 留在目录里，界面只弹"操作失败"。

**修复建议**：`os.replace` 包一层 3 次、每次 120 ms 的重试；失败时清理 `.tmp` 并提示"文件被其它程序占用"；`finally` 中恢复 `holders` 已实现，保持。

## 五、跨模块一致性矛盾

| 编号 | 矛盾 | 证据 | 建议 |
|---|---|---|---|
| C1 | **"特殊章节"三份名单不一致** | `chapflow._SPECIAL_PREFIXES` 含"序""作者的话""内容简介"；`txtconv._SPECIAL_HEAD` 不含；`txtconv._HEADING_RULES` 又是第三套。结果："内容简介"不参与编号、但导入时不会被当作标题分隔 | 抽一份共享常量，三处引用 |
| C2 | **标题规范化两套实现** | 导入用 `txtconv.tidy_title`，编号用 `chapflow._tidy_rest`；行为在"无编号特殊章节"（序章.开端）与全角空格上并不完全等价 | 统一到 `tidy_title`，`_tidy_rest` 调用它 |
| C3 | **标题约束只在部分模式生效** | `MAX_TITLE_LEN=45` 与"不以句末标点结尾"只在 `match_heading` / simple 模式生效，`mode="regex"` 完全不校验，可把整段正文当标题 | regex 模式也套用长度/标点护栏（或文档明确"自定义正则自负其责"） |
| C4 | **`dirty` 一个布尔承担两种语义** | 导出到别处后 `session.dirty=False`，状态栏显示"已保存"，但原文件没动（另有"已导出（原文件未修改）"备注） | 拆成 `dirty`（相对磁盘）与 `exported`（已产出副本），状态栏分别表述 |
| C5 | **"修复 N 项"与实际改动不符** | GUI 只把 `dead`/`empty` 交给修复按钮（`main_window.py:1652`），但 `repair()` 无条件修 `swallow`；`repair_plan` 又把 `swallow` 列为可修 | 三者取同一过滤器；`repair(log)` 返回明确的操作清单 |
| C6 | **错误协议不统一** | `scan_numbering` 返回 `{"error": ...}`，其余 API 抛 `ValueError`；`repair` 返回日志列表；`apply_ops` 外层再包一层 | 只保留"抛异常 + 返回结构"两种形态，并写进 README §4.3 |
